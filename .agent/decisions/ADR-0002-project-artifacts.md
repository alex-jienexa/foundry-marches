# ADR-0002: Документация и исполняемый SQL рядом с PAD

## Context

Владелец предоставил план v0.3, schema.sql и два набора тестов и попросил подготовить локальный импорт без потери смысла. Репозиторий содержит только PAD. Предложена структура docs + .agent + src.

## Decision drivers

Полнота исходников, доступность для новых агентов, отсутствие дублирующих источников истины, совместимость three-way обновления PAD.

## Considered options

1. Хранить только архив — плохо ищется и не связан с задачами.
2. Заменить всё краткими сводками/DBML — потеряются ограничения, функции и продуктовый scope.
3. Полные рабочие разделы + неизменяемые оригиналы + краткая навигация PAD — выбранный вариант.

## Decision

Полная документация в docs; DDL в docs/database/schema.sql; оригинальные проверки в tests/database; исходные четыре файла в docs/reference/originals с хэшами. DBML/ER/каталог генерируются из SQL. `.agent/context/` ссылается на полные источники; единственные ADR/state/protocols остаются в `.agent/`. src пока только описывает будущее размещение кода. Пустой OpenAPI, несуществующие PDF/DOCX и fake runtime не создаются. `.pad/template-base/` не меняется.

Основание согласования — запрос владельца о такой организации артефактов, не отдельное утверждение новых технических/продуктовых решений.

## Consequences

### Positive

Все данные доступны без чата/архива, исходный смысл проверяется картой покрытия и SHA-256, сложные DB-инварианты не теряются в DBML.

### Trade-offs

Исторические оригиналы намеренно дублируют baseline. При развитии проекта обновлять рабочие источники, проекции и проверки, не оригиналы. Разделения плана недостаточно для восстановления отсутствующего ТЗ.
