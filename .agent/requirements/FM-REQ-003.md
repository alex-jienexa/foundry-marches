# 2. Персонажи и Foundry

## Statement

Реализовать весь состав этапа без сокращения: `FoundryGateway`, снимки актёров, привязка с подтверждением, одобрение, лимит, перевод в NPC, XP и уровень, очередь операций

## Rationale and source

Полный [план этапов](../../docs/development/roadmap.md); [профильный полный раздел](../../docs/architecture/foundry.md). Ссылки на сценарии исходного ТЗ сохранены, но само ТЗ отсутствует — не достраивать его по предположениям. [Открытые вопросы](../../docs/development/open-questions.md) решает project-owner перед зависимой реализацией.

## Acceptance criteria

- [ ] Проверки: привязка `POST /api/characters/link`; третий персонаж даёт 409; повтор операции XP не удваивает; остановка relay переводит задачу в «ожидает синхронизации», запуск — в «успех»
- [ ] Итог: персонаж проходит путь от Actor до одобрения, XP и уровень сходятся
- [ ] Для всех операций выполняются серверные permissions/CanSee, журналы/инварианты и безопасность из полных разделов.
- [ ] DB → API/curl → bot → UI, если применимо этапу; источники истины, контекст и тесты обновлены.
