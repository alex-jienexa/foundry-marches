# Происхождение и полнота материалов

В `originals/` лежат все четыре файла из `files.zip` **побайтово без изменений**, с исходными именами. PDF и DOCX в архиве не было — фиктивные файлы не созданы.

- `manifest.json`: размеры и SHA-256 всех оригиналов.
- `coverage.json`: каждый фрагмент исходного Markdown связан с полным рабочим разделом, хэш проверяется автоматически.
- [sources.md](sources.md): внешние ссылки из исходного плана; их актуальность отдельно не исследовалась.

## Рабочие источники истины

1. [Архитектура](../architecture/overview.md) и полный набор разделов в [индексе](../README.md) — все содержательные части исходного Markdown, без сокращений.
2. [schema.sql](../database/schema.sql) — полный исполняемый DDL v0.3, включая триггеры, функции и seed-данные.
3. [Тесты](../../tests/database/README.md) — оригинальные проверки, не сокращённые примеры.
4. Сводки `.agent/context/` — только навигация; не замена спецификации.

При конфликте SQL с описанием текущей структуры таблиц ориентироваться на SQL и зарегистрировать вопрос. При конфликте продуктового намерения с SQL не переписывать ни одно молча: описать расхождение владельцу. DBML, ER и каталог таблиц — генерируемые представления, не миграции.

Оригиналы фиксируют входную версию. Их не редактируют при будущих изменениях проекта. Рабочую документацию и SQL меняют вместе с тестами и ADR; генератор документации запускают повторно. Проверка исходного покрытия действует для импортированной версии; при осознанном развитии разделов обновить политику покрытия отдельной задачей, не переписывать исторические оригиналы.
