# Ограничения исходных материалов и открытые несоответствия

Сохраняются явно, вместо молчаливого «исправления» смысла проекта.

1. Само **ТЗ v1.0 и два дополнения** в архив не вошли. План на них ссылается, но нельзя независимо восстановить полный текст сценариев B–I, разделов 11.5/22 и приоритетов P2. Сценарии и P2 не выдуманы и не объявлены проверенными. Полнота переноса четырёх приложенных файлов проверяема; полнота относительно отсутствующего ТЗ — нет.
2. В §4 исходного плана вместо встроенной архитектурной картинки присутствует текстовый маркер `embedded content`. Изображение отсутствует. Добавленные Mermaid-диаграммы реконструированы по описанию, а не извлечены из картинки.
3. §4.5 упоминает `allow_multi_char`, однако §5.1 и SQL v0.3 используют `adventure_multi_char_grants`. При реализации использовать актуальный SQL-механизм; формулировка исходника оставлена для аудита.
4. `ApplyLevel` требуется в §2.9, но отсутствует в эскизе `FoundryGateway` §2.4. Добавление метода и адаптера — будущая задача, не «готовый интерфейс».
5. В §2.5 упоминается `foundry_snapshot`, в §2.8 — конкретное `foundry_actors.snapshot`; первую формулировку не считать названием дополнительной таблицы.
6. §5.2 — обзорная карта, не полный список всех 115 таблиц: SQL также содержит, например, `political_event_effects` и `event_outbox`. Полный каталог генерируется из SQL, включая поздние ALTER.
7. Общие утверждения исходника вроде «у всех таблиц UUID PK» имеют исключения (составные ключи, `permissions.key`, `event_outbox.id`). Не нормализовать схему под такое обобщение.
8. Числа путешествий в §7.2 прямо помечены автором как взятые по памяти. Версии Foundry/PF2e, возможности relay, WebDAV, Codex и тарифы в этом переносе не подтверждались живыми интеграциями. Это цели Спайка 0, а не результаты импорта.
9. Десять вопросов §10 сохранены [полностью](open-questions.md); ни один ответ не подставлен. Владельцем продуктовых решений остаётся project-owner. Без образцов Codex/заметок нельзя обещать lossless-конвертацию будущих данных.
10. Защита зеркала и сессий `app.*` не заменяет server-side RBAC и безопасную DB-роль. Ограничения SQL проверены тестами; приложение и его модель привилегий ещё не реализованы.

Эти вопросы не блокируют загрузку артефактов; соответствующие части реализации блокируются ими до получения решений/образцов.
