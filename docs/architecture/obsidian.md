## 3. Obsidian и Campaign Codex

Приложение подключается к вашему готовому WebDAV как клиент и сводит три хранилища — Obsidian, БД и журналы Foundry. Плагин синхронизации не нужен.

### 3.1. Что изменилось в решении

- Сервер WebDAV уже настроен, поэтому приложение его не поднимает. В схеме `vault_credentials` (выдача доступа) заменены полями в `vaults`: адрес, корневая папка, логин, зашифрованный пароль, интервал опроса.
- Плагин (Remotely Save и подобные) не участвует: приложение само читает и пишет `.md`. Это снимает проблемы плагинов: в одном из описаний побеждает файл с более поздним временем изменения без слияния ([описание](https://github.com/scruel/obsidian-remotely-save)), а автосинхронизация идёт, только пока открыт Obsidian ([описание](https://github.com/ZeddYu/remotely-save)). Решения о конфликтах принимает приложение.

### 3.2. Campaign Codex

Модуль расширяет журнал Foundry особыми типами листов со связями, не заменяя обычные журналы, и проверен для Foundry 14 ([страница модуля](https://foundryvtt.com/packages/campaign-codex)). Как именно он хранит тип листа и связи, я не проверял, поэтому отображение связей до образцов не проектируем.

- **Спайк 0б.** Выгрузить через relay по 3–5 журналов каждого типа Codex и посмотреть JSON. По нему решаем, где лежат связи (флаги журнала или иное).
- **Целевое отображение.** Тип листа → `wiki_pages.type` и `foundry_journals.sheet_type`; связи Codex → `wiki_relations`.
- **Первый шаг только на чтение:** Foundry → приложение → Obsidian. Запись обратно в журнал включаем после спайка и сначала только для текста и названия.

### 3.3. Потоки данных

| Направление | Как работает | Защита |
| --- | --- | --- |
| Obsidian → приложение | worker раз в `sync_interval_sec` делает `PROPFIND`, сравнивает ETag с `vault_files.remote_etag`, скачивает изменённые `.md`, разбирает свойства заметки | `rev` и хэш, не время |
| Приложение → Obsidian | экспорт новой ревизии записью `PUT` с `If-Match` последнего ETag | ответ 412 = конфликт, файл не затирается |
| Foundry → приложение | хук изменения журнала (SSE) плюс периодическая сверка; HTML страницы журнала → Markdown | флаги `rev` и хэш в журнале |
| Приложение → Foundry | обновление текста журнала, Markdown → HTML | то же + права журнала по `visibility` |
| Obsidian ↔ Foundry | только через БД, прямой связи нет | один источник истины |

### 3.4. Свойства заметки

Обязательные: `id` (постоянный), `type`, `name`, `visibility`. Служебные, их пишет приложение: `rev`, `updated_at`. Остальные свойства уходят в `wiki_pages.attributes` и возвращаются в файл без потерь. Файл без `id` — новая страница; `id` записывается в файл при следующем экспорте. Какие свойства есть в ваших заметках, мне нужно увидеть на образце (вопрос в конце документа).

### 3.5. Конфликты и безопасность данных

1. Единица сравнения — `rev` и хэш содержимого.
2. `rev` файла равен `rev` в БД: правка принимается как новая версия (`source = obsidian`).
3. `rev` файла меньше: трёхстороннее слияние, базой служит версия из `wiki_versions`. Не вышло — в БД остаётся версия приложения, файл мастера сохраняется как `_conflicts/<id>.<время>.md`, создаётся запись `vault_conflicts` и уведомление.
4. Запись всегда с `If-Match`. Поддерживает ли ваш сервер условные запросы, проверяется в Спайке 0б; если нет, перед записью приложение перечитывает ETag и сравнивает хэш (слабее, но работает).
5. Удаление файла переводит страницу в «ожидает удаления»; действует порог массового удаления.
6. **Секреты.** Заметки мастера и страницы `gm_only` попадают только в vault мастера и в журналы, недоступные игрокам. В журналы Foundry с доступом игроков пишется только публичное содержимое. Правило прав журналов подтверждаем на вашем мире.
7. **Бюджет запросов к Foundry.** Журналы читаются пакетами и по событиям, а не опросом (см. 2.7).

### 3.6. Проверки

```bash
# 1. WebDAV отвечает и отдаёт ETag
curl -s -u "$DAV_USER:$DAV_PASS" -X PROPFIND -H "Depth: 1" "$DAV_URL/Vault/" | grep -E "getetag|getlastmodified"

# 2. Условная запись: создаём пробный файл, затем пишем с устаревшим ETag — ждём 412
curl -s -o /dev/null -u "$DAV_USER:$DAV_PASS" -T probe.md "$DAV_URL/Vault/_probe.md"
curl -s -o /dev/null -w "%{http_code}\n" -u "$DAV_USER:$DAV_PASS" -X PUT -H 'If-Match: "stale"' --data-binary @probe.md "$DAV_URL/Vault/_probe.md"

# 3. Приложение забирает заметку и создаёт версию
curl -s -X POST -H "Authorization: Bearer $TOKEN" "$API/api/vaults/$VAULT_ID/sync" | jq '{imported, conflicts, errors}'
curl -s -H "Authorization: Bearer $TOKEN" "$API/api/wiki/pages/npc-0001" | jq '{rev, title}'
```
